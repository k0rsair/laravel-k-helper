# Patch: Auto-trigger Laravel suggestions inside existing strings

Date: 2026-05-21

## Problem

Laravel completions appeared when a trigger character such as a quote, dot, colon, dash, or `>` was typed, but not when the cursor was placed inside an existing string and the user started typing a normal character.

## Root Cause

The extension relied on VS Code completion trigger characters. In many PHP/Blade string contexts, regular typed letters do not invoke the provider when `editor.quickSuggestions.strings` is disabled or not aggressive enough.

## Fix

- Added a lightweight `LaravelAutoSuggestTrigger` document-change listener.
- Added pure context detection in `src/context/autoSuggestContext.ts`.
- Trigger `editor.action.triggerSuggest` only after word-like insertions inside recognized Laravel PHP/Blade contexts.
- Added `laravelKHelper.autoTriggerSuggest` with legacy fallback setting names.
- Added unit coverage for helper strings, model attribute arrays, Blade/Livewire tags, and negative cases.

## Prevention

Keep auto-trigger detection separate from the VS Code runtime listener so context behavior stays unit-testable without importing the `vscode` module.
